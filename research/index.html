Research Interests

My research lies at the intersection of formal methods, software engineering, and IT security & privacy. I develop software engineering methodologies and tools that use formal methods to make security and privacy requirements precise, analyzable, and enforceable.

I investigate how model-driven engineering can be used to develop secure and privacy-by-design software systems. In this approach, security and privacy requirements are specified formally as models in the design phase. These models can then be analyzed and used to generate automatically implementation artifacts.

Security properties

  • Identification: establishing the identity claimed by a user, device, or system.
  • Authentication: verifying that a user, device, or system is who or what it claims to be.
  • Authorization: determining what a user, device, or system is permitted to do.
  • Accountability: ensuring that actions can be attributed to the responsible user, device, or system.

Privacy regulations

  • Lawfulness, fairness & transparency: data is processed lawfully, fairly, and in a transparent manner.
  • Purpose limitation: data is used only for the purposes for which it was collected.
  • Data minimisation: only the data necessary for a purpose is collected.
  • Accuracy: data is kept accurate and, where needed, up to date.
  • Storage limitation: data is kept only as long as the purpose requires.
  • Integrity & confidentiality: data is protected against unauthorised access, loss, or damage.
  • Accountability: the controller can demonstrate compliance with these principles.
  • Lawful basis & consent: processing requires a lawful basis; consent must be freely given and specific.
  • Data subject rights: access, rectification, erasure, restriction, portability, and objection.
  • Data protection by design & by default: protections are built into systems from the outset.
