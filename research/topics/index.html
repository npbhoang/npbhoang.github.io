Research Interests

My research lies at the intersection of formal methods, software engineering, and IT security & privacy. I develop software engineering methodologies and tools that use formal methods to make security and privacy requirements precise, analyzable, and enforceable.

During my master and doctorate study, I investigated how model-driven engineering can be used to develop secure and privacy-by-design software systems. In our approach, security and privacy requirements are specified formally as models in the design phase. These models can then be analyzed and used to generate automatically implementation artifacts.

I am also interested in different security and privacy properties.

Security properties

  • Identification: establishing the identity claimed by a user, device, or system.
  • Authentication: verifying that a user, device, or system is who or what it claims to be.
  • Authorization: determining what a user, device, or system is permitted to do.
  • Accountability: ensuring that actions can be attributed to the responsible user, device, or system.

Privacy regulations

  • Lawfulness, fairness & transparency: data is processed lawfully, fairly, and in a transparent manner.
  • Purpose limitation: data is used only for the purposes for which it was collected.
  • Data minimisation: only the data necessary for a purpose is collected.
  • Accuracy: data is kept accurate and, where needed, up to date.
  • Storage limitation: data is kept only as long as the purpose requires.
  • Integrity & confidentiality: data is protected against unauthorised access, loss, or damage.
  • Accountability: the controller can demonstrate compliance with these principles.
  • Lawful basis & consent: processing requires a lawful basis; consent must be freely given and specific.
  • Data subject rights: access, rectification, erasure, restriction, portability, and objection.
  • Data protection by design & by default: protections are built into systems from the outset.

Model-driven Privacy

Model-driven privacy (MDP) is a software development methodology in which privacy requirements are specified as models and enforcement mechanisms are generated automatically via model transformations. A developer writes three interconnected declarative models, i.e., a data model describing the state space, a security model capturing fine-grained access control, and a privacy model expressing data-protection requirements. The methodology generates a web application that is security- and privacy-aware by design.

Enforcing Fine-grained Access Control on Data-centric Applications

Fine-grained access control (FGAC) policies are policies that authorization decisions based not only on a user's role and the data they are permitted to act on, but also on contextual conditions that may depend on the current state of the application. Enforcing such policies in data-centric applications is challenging becauese access control rules are often manually implemented and scattered across the codebase, making them error-prone and difficult to maintain. To address this challenge, we aim to make FGAC policies explicit and enforce them systematically at the data layer, e.g., by rewriting SQL queries or intercepting the object-relational mapper so that personal data never leaves the database unchecked.
